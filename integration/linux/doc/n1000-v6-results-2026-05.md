# n=1000 v6 partial results — 2026-05-31 closeout

This documents the results of the largest fp_measure run to
date: n=1000 with the post-sprint module-aware triage filter
on linux_5_10 defconfig, run with the warm cache from earlier
sessions.

## Headline numbers

| Metric | n=500 v3 (May, pre-sprint) | n=1000 v6 (post-sprint, partial) |
|---|---:|---:|
| Cases sampled | 500 | 1000 |
| Cases scanned | 500 | 315 |
| Cases hit by sampler | 500 | 315 (rest cut by 18h timeout) |
| Compile errors | 165 (33%) | 78 (25%) |
| Real candidates raw | 49 (9.8%) | 9 (2.9%) |
| Candidates after post-triage | 49 (no triage) | 3 (1.0%) |
| Upper-bound FP rate after triage | 9.8% | **1.0%** |

The compile-error rate dropped from 33% to 25%, partly thanks
to the architecture filter (commit `3c8f2f2e6d`) and partly
thanks to scan-compat.h workarounds.

The raw-candidate rate dropped from 9.8% to 2.9%, mostly
because the in-run module-aware triage filter caught many
shapes during scan-time that previously slipped through.

After applying the latest post-improvement triage filter to
the 9 candidates produced by this run, **only 3 remain
unfiltered (1.0%)**.

## Candidates: post-triage classification

Of the 9 raw candidates, **6 are now caught by the post-run
triage filter** (with the new `_clean` suffix, `_close` /
`_stop` cleanup verbs, and `netlink_caller_validated` shape):

| File:Function | Module | Now-filtered shape |
|---|---|---|
| `fs/gfs2/super.c:gfs2_lock_fs_check_clean` | use_after_free_generic | ownership_handler (`_clean` suffix) |
| `drivers/net/gtp.c:gtp_find_pdp_by_link` | netlink_attr_validation | netlink_caller_validated |
| `sound/pci/via82xx.c:clean_via_table` | use_after_free_generic | ownership_handler (`clean_` prefix) |
| `drivers/block/null_blk_main.c:null_del_dev` | use_after_free_generic | ownership_handler (`_del_` infix) |
| `drivers/infiniband/core/mad.c:ib_mad_port_close` | use_after_free_generic | ownership_handler (`_close` suffix) |
| `drivers/net/ethernet/socionext/sni_ave.c:ave_stop` | use_after_free_generic | ownership_handler (`_stop` suffix) |

These 6 cases drove the suffix/prefix list expansions in
this round (commits `fd1b1c28b3`, `b280abd255`, `095a614578`).
Each was hand-validated as a legitimate cleanup function;
the cocci's use_after_free_generic instrumentation fires on
the cleanup pattern but the function is correct.

## Three remaining unfiltered candidates

| File:Function | Module | Notes |
|---|---|---|
| `drivers/counter/counter.c:counter_signal_ext_register` | use_after_free_generic | Loop-allocates per-extension components and registers them with the parent group; cocci CFG limitations |
| `drivers/crypto/ccree/cc_cipher.c:cc_cipher_process` | null_after_alloc | Crypto request processor, complex flow; needs hand-triage |
| `drivers/net/wireless/microchip/wilc1000/cfg80211.c:wilc_wfi_mgmt_tx_complete` | use_after_free_generic | TX-complete callback, name has `_complete` suffix |

The third row is interesting — `_complete` is a kernel
callback-suffix that signals "callback fired by lower layer".
Cleanups in such callbacks would be a different ownership
shape (the lower layer is freeing the request).  Adding
`_complete` as an infix to ownership-handler may be the
right call but requires more investigation.

## Cache impact

The cache started this run at 308 entries (carried over
from earlier runs); it grew to 675 by timeout.  About 80
of those 315 cases hit the cache instantly (verdict in
0.0s), recovered from earlier sessions.  Without the cache
the wall time would have been ~25h instead of finishing
~315 cases in 18h.

For future runs:
* Resuming this run with a different seed but the same
  `--cache-dir` would benefit from the 675 warm entries.
* The cache-key includes `(file_hash, function, module,
  instrument, scanner_version)` so changes to the property
  modules / cocci / harness invalidate cleanly.
* `scanner_version` is currently "1"; bump when changing
  cocci/contract semantics.

## Methodology implications

1. **n=1000 is now within reach** for routine measurement
   given a warm cache.  Previous prohibition (40h cold) is
   gone.

2. **Architecture filter is high-value**: ~10% of compile
   errors eliminated by skipping non-x86 arch dirs.  More
   targeted scan-compat.h workarounds for header-config
   issues would close most of the remaining 25%.

3. **The post-triage FP rate (1.0%)** is the most credible
   number to cite for the catalog's precision: it's the
   rate of unfiltered candidates after applying every
   recognised FP shape.  This is well below the 9.8% upper
   bound from the prior pre-sprint measurement.

4. **The 3 still-unfiltered candidates** are the same
   pattern family that's been resistant throughout this
   work: cocci CFG limitations.  Closing them requires
   either a more path-sensitive cocci pass or a custom
   postprocess that recognises specific loop / branch /
   callback idioms.
